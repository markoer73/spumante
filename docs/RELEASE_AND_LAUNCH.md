# Spumante Release, Homebrew Cask & Community Launch Kit

This guide contains everything needed to publish a signed/notarized GitHub Release of **Spumante for macOS**, set up the **`brew install --cask` Homebrew Tap**, and announce Spumante on **Hacker News (`Show HN`)**, **Reddit**, and curated macOS directories.

---

## 1. Publish the `v1.0.0` GitHub Release

```sh
# 1. Build (and optionally sign + notarize with -nz) the self-contained macOS DMG
./scripts/build.sh --dmg -nz

# 2. Verify the generated DMG, SHA-256 checksum, and stamped Homebrew Cask
ls -lh builds/Spumante-Installer.dmg builds/Spumante-Installer.dmg.sha256 builds/spumante.rb

# 3. Create and push the v1.0.0 tag, then upload the DMG to GitHub Releases
git tag -a v1.0.0 -m "Spumante v1.0.0 for macOS"
git push origin main --tags

gh release create v1.0.0 \
  builds/Spumante-Installer.dmg \
  builds/Spumante-Installer.dmg.sha256 \
  --title "Spumante v1.0.0 for macOS (Apple Silicon & Intel)" \
  --notes-file docs/RELEASE_AND_LAUNCH.md
```

---

## 2. Publish the Homebrew Tap (`brew install --cask markoer73/spumante/spumante`)

Create a public GitHub repository named **`homebrew-spumante`** under `github.com/markoer73/homebrew-spumante` containing `Casks/spumante.rb`:

```sh
# Copy the SHA-256-stamped Cask generated by ./scripts/build.sh --dmg
mkdir -p /tmp/homebrew-spumante/Casks
cp builds/spumante.rb /tmp/homebrew-spumante/Casks/spumante.rb
cd /tmp/homebrew-spumante
git init && git branch -M main
git add Casks/spumante.rb
git commit -m "spumante 1.0.0"
gh repo create markoer73/homebrew-spumante --public --source=. --push
```

Once pushed, any macOS user can install Spumante with a single command:

```sh
brew install --cask markoer73/spumante/spumante
```

## 3. Ready-to-Use GitHub Release Notes (`v1.0.0`)

```markdown
## Spumante v1.0.0 for macOS 🥂

Run Windows `.exe` and `.msi` applications directly on macOS (Apple Silicon & Intel) with native Metal graphics, Retina High-DPI, a persistent macOS Menu Bar tray app, and built-in zero-trust security & Seatbelt sandboxing.

### Highlights

- **100% Self-Contained, Python-Free Native Runtime**:
  - `Spumante.app` and `Spumante Config.app` are native C/Objective-C macOS bundles with the Wine runtime and macOS parity overlays bundled inside `Spumante.app/Contents/Resources/`. Zero Python, Xcode, or Homebrew dependencies are required at runtime.
- **macOS Menu Bar Tray App (`NSStatusItem`) & 5-Tab Native Settings UI**:
  - Stays available in the macOS menu bar with the Spumante flute icon for 1-click access to your **Favourite Windows Apps** (with custom display labels), **Windows Utilities** (`Task Manager`, `Command Prompt (wineconsole.exe)`, `Notepad`, `Registry Editor`, `Wine Configuration`, `File Explorer`), **More Built-in Apps**, **Spumante Settings**, **Sync Installed `drive_c` Apps (`+x`)**, and 1-click **Bug / AppDB Reporting**.
  - Cascades Windows version (`win11` / `win10` / `win81` / `win7`), Retina/HiDPI mode, and DLL overrides directly to `$WINEPREFIX/user.reg` without needing `winecfg`.
- **Zero-Trust Security & macOS Seatbelt Containment by Default**:
  - Enforces the POSIX executable bit (`chmod +x`) on external `.exe` and `.msi` files (and automatically syncs `+x` across `$WINEPREFIX/drive_c` after any Windows installer completes).
  - Runs a 3-gate pre-execution PE security scanner (Gate 1: macOS Quarantine / MotW; Gate 2: PE Authenticode CMS SHA-256 signature verification; Gate 3: W^X section & suspicious IAT analysis + optional VirusTotal v3 cloud hash lookup).
  - Wraps Windows apps in an XNU `sandbox-exec` Seatbelt profile with `Z:` stripped, `~/.ssh`, `~/.aws`, `~/.gnupg`, and Keychains blocked, incoming connections denied, and outgoing traffic restricted to HTTP/HTTPS/DNS (`80`, `443`, `53`) by default.
- **Apple Silicon & Native macOS Framework Parity**:
  - `ntdll` 16 KB host page vs. 4 KB Windows `PAGE_GUARD` / `MEM_WRITE_WATCH` emulation, Darwin XNU `__ulock_wait2` / `__ulock_wake` (`NTSync` parity), `winemac.drv` `IOSurface`-backed `CAMetalLayer` swapchains, `mfplat` `VideoToolbox` H.264/HEVC hardware decode, `qcap` `AVFoundation` video + `CoreAudio` capture, `d2d1` `vkd3d-shader` Metal Shading Language (MSL) compiler, and `wineusb.sys` / `winebth.sys` `IOKit` USB & Bluetooth backends.

### Installation

- **Option A — DMG Installer**: Download `Spumante-Installer.dmg` below, open it, and double-click **`Install Spumante.command`**.
- **Option B — Homebrew Cask**:
  ```sh
  brew install --cask markoer73/spumante/spumante
  ```
```

## 4. Hacker News (`Show HN`) Launch Copy

**Title:**
> `Show HN: Spumante – Run Windows .exe/.msi apps on macOS in a zero-trust Seatbelt sandbox`

**URL:**
> `https://github.com/markoer73/Spumante`

**First Comment (post immediately after submitting):**
> Hi HN! I built **Spumante** (`https://github.com/markoer73/Spumante`), an open-source (Apache 2.0 launcher/tooling + LGPL-2.1 Wine overlays) runtime and native macOS menu bar app for running Windows `.exe` and `.msi` applications on Apple Silicon and Intel Macs.
>
> **Why build this?**
> 1. **Running untrusted Windows `.exe` files under default Wine is a security nightmare.** Out of the box, Wine maps your entire macOS filesystem to `Z:\` and runs with full access to `~/.ssh`, `~/.aws`, your macOS Keychain, and unrestricted inbound/outbound sockets. Spumante enforces `chmod +x` on external `.exe`/`.msi` files, runs a 3-gate pre-execution PE scanner (macOS Quarantine check, PE Authenticode SHA-256 verification, static W^X/IAT analysis + optional VirusTotal v3 lookup), unlinks `Z:`, and wraps execution inside a generated macOS XNU `sandbox-exec` Seatbelt profile that blocks sensitive host paths and restricts network access to HTTP/HTTPS/DNS by default.
> 2. **Native macOS UX without `winecfg` or scripting dependencies.** `Spumante.app` and `Spumante Config.app` are written in pure C and Objective-C/AppKit with the Wine runtime bundled inside the app. Double-clicking any `.exe` or `.msi` in Finder launches it directly, and the Spumante flute icon stays in your macOS menu bar so you can launch custom-labeled favourite Windows apps, Task Manager (`taskmgr.exe`), Command Prompt (`wineconsole.exe`), or tweak settings that cascade non-destructively into `user.reg`.
> 3. **LLM-accelerated macOS subsystem parity via differential testing.** Upstream Wine has an anti-LLM policy, so we maintain our macOS enhancements as clean overlays verified against a genuine Windows 10/11 QEMU VM ground-truth oracle and upstream `winetest` suites (with ASan+UBSan). That allowed us to implement 16 KB vs. 4 KB sub-page `PAGE_GUARD`/`MEM_WRITE_WATCH` emulation on Apple Silicon, Darwin `__ulock_wait2` `WaitOnAddress` (`NTSync`) parity, `IOSurface`-backed `CAMetalLayer` child-window swapchains, `VideoToolbox` H.264/HEVC hardware decoding, `AVFoundation` capture, and `IOKit` USB/Bluetooth drivers (`wineusb.sys`, `winebth.sys`).
>
> You can grab the self-contained `.dmg` from Releases, install via `brew install --cask markoer73/spumante/spumante`, or build from source in two commands (`./scripts/build.sh --full-x86 && ./scripts/build.sh --dmg`). Feedback and AppDB reports are very welcome!

- **Title:** `Spumante – Running Windows PE (.exe/.msi) binaries on macOS inside a zero-trust XNU Seatbelt sandbox with pre-execution PE/Authenticode/VirusTotal scanning`
- **Body:**
  > If you ever need to run a Windows `.exe` utility or inspect a PE binary on macOS without booting a full Windows VM, running standard Wine is risky because Wine maps `/` to `Z:\` and grants unrestricted access to your host files and network.
  >
  > **Spumante** (`https://github.com/markoer73/Spumante`) is a native C/Objective-C macOS launcher and Wine runtime that enforces host-side zero-trust containment before `wineserver` ever boots:
